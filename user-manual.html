eConstruction Supply Platform User Manual

Standard Operating Procedures, role-based workflows, interactive interface guides, and system configuration reference for the multi-vendor construction e-commerce and POS platform.

Production: econstruction-supply.site
Version 2.0 (PostgreSQL + Docker)
Enterprise Multi-Vendor Architecture
1. Platform Architecture & Roles Overview
Architecture

The eConstruction Supply platform connects construction material manufacturers, trade suppliers, commercial contractors, and retail shoppers into a unified real-time supply chain ecosystem.

System Portals & User Matrix
Role Portal URL Primary Responsibilities Default Landing
Customer / Contractor /index.php Browse catalog, select product variants, request quotations (RFQ), checkout via Cash or Purchase Order (PO), and track orders. customer-profile.php
Global Super Admin /admin/ Manage product category hierarchy (Top, Mid, End), approve and monitor vendors, configure global logistics, manage master settings. admin/index.php
Supplier Admin /supplier/ Manage catalog inventory, process incoming orders, transition orders to "Paid Orders", quote RFQs, view sales reports & analytics. supplier/index.php
Supplier POS Cashier /supplier/pos.php Execute walk-in (OTC) and registered user sales, select item variants, compute change, apply barangay delivery fees, print receipts. supplier/pos.php
2. Customer & Contractor User Manual
Customer Portal
2.1 Account Registration & Login
  • Navigate to Registration
    Open registration.php from the top navigation bar.
  • Enter Account Details
    Provide your Full Name / Contractor Entity Name, Email, Contact Phone, and accurate Delivery Address (Street, Barangay, Municipality, Province, Zip).
  • Account Verification & Login
    Log in at login.php to access personalized contractor pricing, saved carts, and order history.
2.2 Browsing Category Hierarchy & Search

Construction materials are structured in a 3-tier hierarchy: Top Category (e.g. Structural Steel) → Mid Category (e.g. Hollow Sections) → End Category (e.g. Tubular).

Search Tip: Use the top search bar to type keywords like "Tubular 2x3", "Plywood 1/4", or "Angle Bar Green" to find exact matches.
2.3 Parent Product Cards & Interactive Variant Selection Modal

To prevent product clutter, multiple sizes, thicknesses, and colors of the same product are grouped into a single Parent Product Card.

+-------------------------------------------------------------+ | [END CATEGORY: TUBULAR] [245 IN STOCK] | | | | [ PRODUCT PHOTO ] | | | | Tubular Steel | | [ 17 Variants / Sizes Available ] | | Price: ₱285.00 - ₱1,983.00 | | Rating: ★★★★☆ (12 reviews) | | | | [ + Add / Select Variant ] | +-------------------------------------------------------------+
  • Open Variant Modal
    Click on the parent product card or the "+ Add / Select Variant" button.
  • Select Size / Thickness / Spec
    Choose from the dropdown or click one-tap Variant Chips (e.g., 2" x 3" (t = 1.2, Orange)).
  • Review Live Price & Stock Level
    The modal instantly displays the selected SKU, current in-stock quantity, and unit price.
  • Set Quantity & Add to Cart
    Use [-] and [+] to set the quantity (system locks quantity to available inventory) and click "Add to Cart".
2.4 Request for Quotation (RFQ) Workflow

Ideal for commercial builders, large structural jobs, and institutional buyers needing wholesale volume discounts.

  • Initiate RFQ
    Click "Request a Quote" on any product page or navigate to rfq.php.
  • Submit Bill of Materials (BOM)
    Specify required quantities, requested delivery schedule, job-site location, and custom specs.
  • Review Supplier Proposal
    Go to Customer Dashboard → "My RFQ Quotations" to review the supplier's discounted unit prices, validity date, and terms.
  • Accept & Convert to Order
    Click "Accept Quotation" to automatically convert the quote into an active project order.
2.5 Purchase Order (PO) Checkout & Transaction ID Receipt

For corporate contractors purchasing on account terms:

  • Proceed to Checkout
    On checkout.php, review delivery address and line items.
  • Select "Send Purchase Order"
    Click the "Send Purchase Order" payment button.
  • Generate Official PO Receipt with Transaction ID
    The platform automatically assigns a verified Transaction ID (e.g. TXN-PO-1725499200-842) and renders purchase-order-receipt.php.
  • Print or Export PDF
    Click "Print Purchase Order" to submit the document directly to your accounts payable department.
3. Global Admin User Manual & Configuration
Super Admin
3.1 Portal Access & Security

Access the Global Admin panel at https://econstruction-supply.site/admin/.

3.2 Category Hierarchy Management

Maintain the 3-level taxonomy from the left navigation sidebar:

  • Top Level Category (admin/top-category.php)
    Defines major departments (e.g., Structural Steel, Plumbing, Electrical, Masonry). Controls top navbar visibility.
  • Mid Level Category (admin/mid-category.php)
    Sub-branches under Top Category (e.g., Hollow Structural Sections, Schedule 40 Pipes).
  • End Level Category (admin/end-category.php)
    Terminal categories where products reside (e.g., Tubular, Angle Bar, Deformed Bar, PVC Conduit).
3.3 Global Logistics & Barangay Management

Manage delivery zones and transportation costs across all municipalities and barangays:

  • Barangay Database (tbl_brgy): Contains all local districts, linked municipalities, and baseline shipping costs.
  • Municipality Management (admin/municipality.php): Add, edit, or remove delivery jurisdictions.
4. Supplier Admin User Manual
Supplier Portal
4.1 Product Catalog & Automatic Variant Parsing

When creating product variants in supplier/product-add.php, use standard construction delimiters. The system's intelligent parser automatically extracts size, thickness, color, rating, and length to group them into 1 Parent Product Card.

Recommended Naming Conventions:
• Tubular - 2" x 3" (t = 1.2, Orange)
• Angle Bar - 1 1/2" x 1 1/2" (t = 3/16, Green)
• Deformed Bar 16mm (D = 16 mm, Blue)
• Rotary Hammer 850W (220V)
4.2 Order Management: "Receive Orders" vs "Paid Orders"

The supplier sidebar provides two synchronized order management databases:

Section File / URL Description & Function
Receive Orders supplier/order.php Contains all incoming orders, COD bookings, and unpaid Purchase Orders awaiting payment verification.
Paid Orders supplier/paid-orders.php Dedicated database table containing all fully settled and paid orders for fulfillment and accounting.
Automatic Order Movement: When the supplier changes an order's Payment Status to "Paid" in supplier/order.php, the order is automatically relocated into the "View Paid Orders" database table!
  • View Customer Purchase Orders
    In supplier/order.php, locate the order row and click the blue "Purchase Order" button under the Payment Information column to inspect the full PO.
  • Confirm Payment & Update Status
    Change Payment Status to "Paid". The order moves to paid-orders.php.
  • Update Shipping Status
    Progress delivery status: Pending → Processing → Delivered.
4.3 Sales Reports & Analytics Engine

Located on the sidebar under "Sales Report" (supplier/sales-report.php):

  • Multi-Period Filtering
    Filter sales data by Day, Week, Quarterly (Q1-Q4), and Yearly.
  • KPI Executive Metrics
    View instant calculations for Gross Revenue, Net Paid Orders, Total Units Sold, and Average Order Value (AOV).
  • Visual Analytics & Export
    Interactive revenue trend charts, category performance breakdowns, and one-click Export to CSV / PDF.
4.4 Delivery Cost & Barangay Rate Configuration

Navigate to supplier/shipping-cost.php:

  • Delivery Cost (All Towns): Sets the universal default shipping rate.
  • Barangay Surcharges: Set customized shipping tariffs per individual barangay.

5.3 Special Order (Manual Product Entry)

When a customer requests an uncatalogued or custom construction item (e.g. customized fabrication, custom dimension pipes, non-standard brackets):

  • Click "+ Special Order"
    Located right next to the search bar in the Products Available section.
  • Fill in Required Item Details
    • Product Name *: Enter custom name (e.g. Stainless Steel Pipe).
    • Product Details / Specification: Multiline field for custom size, thickness, alloy, length, or customer notes.
    • Unit Price *: Enter negotiated unit price (e.g. ₱1,250.00).
    • Quantity *: Use [-] and [+] to set quantity.
  • Review Total & Add to Cart
    The modal automatically generates a unique Special Order Reference (e.g. SO-20260905-4812) and computes Total Amount = Price × Qty. Click "Add to Cart".
  • Special Order Cart & Zero Inventory Deduction
    The item appears with a bright [SPECIAL ORDER] badge. Special orders do NOT deduct stock from existing catalogue inventory.
5.4 Customer Types & Independent Location Delivery Toggle
  • Customer Selection
    Choose Walk-in (OTC) for counter shoppers or Registered User to attach the sale to a registered contractor account.
  • Independent Location / Delivery Button
    The "Location" radio button operates independently from customer selection:
    • Inactive (Unchecked): Delivery fee is ₱0.00 (Store pickup).
    • Active (Checked): Displays the Barangay Dropdown (populated from tbl_brgy). Selecting a barangay dynamically adds its exact delivery fee to the sale.
5.5 Finalizing Sale & Receipt Generation
  • Add Items & Select Variants
    Click product cards, pick variant specifications in the modal, set quantities, and add to current sale.
  • Enter Cash Tendered
    Type amount received. POS immediately computes Change Due.
  • Complete Sale & Print
    Click "Complete Sale & Print Receipt". Catalogue product inventory is deducted (Special Orders bypass stock deduction), sale record saved, and printable receipt generated with Special Order badges.
5.6 Return Item Processing & Workflow

When a customer brings back an item purchased through the POS or online store, the cashier can process an authoritative return and refund directly in the POS without altering past sales history:

+---------------------------------------------------------------------------------------------------------+ | [ RETURN / REFUND PROCESSING MODAL ] | +---------------------------------------------------------------------------------------------------------+ | [ Search Order / Invoice / Customer Name / Phone / Email / Product SKU... ] | | | | Order: POS-1757064903 | Date: 2026-09-05 | Customer: Juan Dela Cruz (09171234567) | Total: ₱14,500.00 | | +-----------------------------------------------------------------------------------------------------+ | | | Product: Deformed Steel Bar 16mm (Grade 40) | Sold Qty: 20 | Returned: 0 | Remaining: 20 | | | | Unit Price: ₱485.00 | Line Total: ₱9,700.00 [ RETURN THIS ITEM ] | | | +-----------------------------------------------------------------------------------------------------+ | | | | RETURN CONFIGURATION: | | Return Qty: [-] [ 5 ] [+] (Max returnable: 20) | | Reason: [ Defective / Damaged Item v ] | | Item Condition: [ Resellable (Restock to Inventory) v ] -> RESTOCK ALERT: +5 units added to stock | | Refund Method: [ Original Payment (Cash) v ] | | Refund Calculation: 5 units x ₱485.00 = ₱2,425.00 | | | | [ CANCEL ] [ CONFIRM & PROCESS REFUND ] | +---------------------------------------------------------------------------------------------------------+
  • Step 1: Open Return Modal
    Click the red [ RETURN ] button located next to the Special Order button in the POS header.
  • Step 2: Search Completed Sale
    Enter the Invoice ID / Payment ID (e.g., POS-1757064903), customer name, phone number, email address, or product SKU. The system instantly lists matching completed orders belonging to your supplier account.
  • Step 3: Select Item & Verify Remaining Returnable Limit
    The modal displays each line item in the order with its originally purchased quantity, previously returned quantity, and current Remaining Returnable Quantity. Items already 100% returned are disabled. Click "Return This Item" on the target line item.
  • Step 4: Configure Quantity, Reason, Condition & Refund Method
    • Quantity to Return: Set within allowed range (1 up to Remaining Returnable). Cannot exceed purchased amount.
    • Return Reason: Select from Defective / Faulty, Wrong Item Supplied, Customer Changed Mind, Damaged in Transit, Quality Not as Expected, or Other Reason (with mandatory details).
    • Item Condition & Restock Logic:
      - Resellable / Unopened / New: Automatically restores stock to catalogue inventory (tbl_product.p_qty).
      - Damaged / Defective / Broken / Needs Inspection / Used: Does NOT restock to catalogue inventory.
      - Special Order items: Always bypass catalogue restock (since they are uncatalogued custom items).
    • Refund Method: Select Cash, Original Payment Method, Store Credit, or Bank Transfer.
    • Authoritative Server Calculation: Refund is strictly computed server-side using original recorded purchase price: Refund = Return Qty × Unit Price.
  • Step 5: Process Return & Print Return Slip
    Click "Confirm & Process Refund". The system generates an official Return Reference (e.g. RET-20260905-9214), executes atomic database persistence, updates stock if condition permits, and renders a printable Return & Refund Slip formatted for 80mm thermal receipt printers.
5.7 Return History & Audit Trail (supplier/returns.php)

Suppliers can review and audit all past return transactions by clicking Return History in the sidebar or POS header:

  • KPI Overview Cards
    View instant totals: Total Return Records, Total Refund Amount (₱), Restocked Inventory Units, and Non-Restocked Units.
  • Detailed Search & Filter
    Filter records by date range, refund payment method, or item condition (Resellable vs Damaged).
  • Reprint Return Slips
    Click "View Slip" on any return record in the table to view the full audit breakdown, cashier notes, restock status, and reprint official return slips at any time.
5.8 Sales Reports & Net Sales Revenue (supplier/sales-report.php)

Returns are fully integrated into financial sales reporting with real-time net calculations:

  • Gross Sales Revenue: Sum of all completed sales during the selected period (Daily, Weekly, Quarterly, Yearly, or Custom Date Range).
  • Total Returns & Refunds: Sum of all processed refunds issued during that exact period.
  • Net Sales Revenue: Mathematically computed as Gross Sales - Total Returns to reflect true supplier earnings.
  • Returns Table Breakdown: Itemized listing of each return transaction with reference number, customer name, reason, restock badge, and refund amount.
6. System Configuration, Database & Deployment
DevOps & Admin
6.1 Database Schema & Key Entities

The platform runs on PostgreSQL 14 within container econstructionsite-db.

Table Name Primary Keys / Foreign Keys Purpose
tbl_product p_id, ecat_id, supplier_id Product catalog items, prices, stock quantities (p_qty), and image filenames.
tbl_order id, order_id, product_id, payment_id Itemized purchase order line items, selected sizes, colors, and quantities.
tbl_payment id, payment_id, txnid, customer_id Payment ledger, transaction identifiers, payment status, and shipping fees.
tbl_returns return_id, return_reference, payment_id, supplier_id Return transaction header recording refund amounts, payment method, customer details, and audit timestamps.
tbl_return_items return_item_id, return_id, order_item_id, product_id Itemized return lines recording returned quantities, reason, condition, and inventory restock status.
tbl_brgy brgy_id, m_id Barangay shipping matrix with localized transportation costs.
tbl_rfq rfq_id, customer_id, supplier_id Request for quotation requests, quoted unit rates, validity dates, and status.

6.3 Troubleshooting & Operational Solutions
Issue / Error Cause Resolution
Headers already sent error Whitespace or BOM before <?php tag Save files with UTF-8 without BOM; ensure no trailing spaces before opening PHP tag.
Products appearing as separate cards Missing standard delimiter in product title Rename product variant with format: Base Name - Dimension (Spec).
Paid orders not in "Paid Orders" tab Payment status not set to "Paid" Update Payment Status to Paid in supplier/order.php; system automatically relocates it.
POS delivery fee not adding to total Location toggle is inactive Click the Location radio button in POS card to activate Barangay fee selector.
